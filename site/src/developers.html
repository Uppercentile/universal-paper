The problem

Three systems. Three copies. One deal.

The GPO's contract system, the supplier's ERP and the member's spreadsheet each hold their own version of the same agreement. Teams spend weeks reconciling them. Universal Paper gives all three the same record, with a fingerprint that proves they match. Here's how that works.

  1. 01 · Write it once

    Three systems, one form

    The GPO's contract system, the supplier's ERP and the member's spreadsheet each describe the same deal. Universal Paper gives it one shape: plain JSON built from standard Terms, with the parties' own numbers.

  2. 02 · Fingerprint it

    A name computed from the content

    Canonical JSON (RFC 8785) plus SHA-256 turns the agreement into 64 characters. Any system, in any language, computes the same ones.

  3. 03 · Sign the fingerprint

    Signatures cover exactly this text

    Each party signs the hash with Ed25519. The signature covers these Terms and these numbers, nothing more and nothing less.

  4. 04 · Let the data do the math

    Everyone derives the same fee

    When January's sales report arrives, every party's software computes the same fee and due date from the signed clause. Nobody re-keys a number.

  5. 05 · Catch any change

    One digit breaks the proof

    Change the rate after signing and the fingerprint no longer matches. Every party's software rejects the copy, offline, without asking anyone.

  6. 06 · Keep private terms private

    Sealed values still verify

    A Seal hides a value from parties who shouldn't see it (A10). They still check the signatures and reach the same verdicts.

Core concepts

      
Small enough to check by hand. Complete enough to run a contract.

      
The bundle you just validated is built from seven primitives, two value types and six clause forms. Each primitive does one thing, and the list is short on purpose because every primitive is a permanent commitment.

    

    

      
Primitive
Agreement
The cover page: Parties in Roles, plus Clauses that apply standard Terms with values. Its hash is what everyone signs.
{"type": "Agreement", "spec": "UP/0.1-draft", "parties": […], "clauses": […]}

      
Primitive
Party
Anything that can sign. A Party is its Ed25519 key.
"ed25519:315acb5c…"

      
Primitive
Role
What a Party does in one Agreement.
aggregator · supplier · member

      
Primitive
Term
Standard meaning with a stable id, pinned by hash.
"UP:Admin-Fee"

      
Primitive
Event
A signed change. Only three kinds exist.
propose · accept · attest

      
Primitive

Where an Agreement stands. Never written, always computed from its chain, so every evaluator gets the same answer.
"status": "executed", "height": 9, "last": "sha256:68b6d6b8…"

      
Primitive

Bounded authority for an agent.
"rate": {"max": "0.03"}

      
Value type
Identifier
Reuses GTIN, GLN, HIN, NDC. Never mints IDs.
{"scheme": "GTIN", "id": "…"}

      
Value type
Seal
A salted hash in place of a private value.
{"seal": "sha256:41135ba3…"}

Every Term is built from these. A new Term never needs new code.

Content-addressed RFC 8785
Every object is named by the SHA-256 of its canonical JSON. Same content, same name, on every machine.

      
Deterministic A4
State is computed from the chain, never stored. Two evaluators with the same events always agree.

      
Value-neutral A6
Terms define meaning, never numbers. The library can't suggest a price, rate or period.

      
Ricardian A8
The signed contract text is generated from the data, under the same hash. They can't drift.

      
Bounded delegation A9
Agents act under Mandates. Anything outside the bounds is invalid for every evaluator.

      
Confidential by construction A10
Seals hide private values while hashes, signatures and states still verify.

    


    

      
Terms as data

      
Scroll to watch a clause become data

      
The real UP:Admin-Fee Term. Its prose and its machine meaning share one hash, so they can't drift apart.

    

    

      

        
1 · The prose
It starts as contract language
The rendering template has a slot for each value the parties choose. There are no numbers in it.

        
2 · Parameters
Every slot is a typed parameter
Name, type and description, and nothing else. There's no field for a default value, so the library can't suggest a price or rate (axiom A6).

        
3 · Machine meaning
The meaning is a Duty form
Who owes whom, how often, by when, how the amount is computed, and what discharges it.

        
4 · A clause
The Agreement binds values
The clause pins the exact Term definition by hash in def and supplies every parameter.

        
5 · Back to prose
The signed text is generated
up render fills the template. Everyone gets the same sentence, byte for byte (axiom A8).

Proof, not trust

      
Every object has a fingerprint. Try to change one.

      
Every Term, Agreement, Event and State you just met is identified by the SHA-256 hash of its canonical JSON (RFC 8785). The same content gives the same hash on any machine, in any language, and that is what lets parties trust the math instead of each other.

Signatures and chains

      
History is a single signed line. Tampering breaks it.

      
Each Event is signed over its hash and names the State before it. This is the real master chain, then the repo's fault example.

    

    

      

        
genesis
The proposal starts the chain
Its hash becomes the ChainId, the agreement's permanent identity, even through later amendments.

        
prev → state
Each event commits to what came before
The supplier's accept names the State it saw in prev. Two events can't both follow the same State, so there's never a fork to argue over.

        
nine events
Every evaluator lands on the same State
After nine events, every copy reaches sha256:f7ca8ea5…. What's owed comes from up derive, never from a stored balance.

        
fault example
Change one number in one copy
In the supplier ERP's copy, the fee rate was changed from 2% to 1.5% after signing. The genesis event's hash changes, the aggregator's signature fails, and that copy stops at event #0.

Questions

      
What developers ask first

      
Short answers, with the part of the spec that backs each one.

    

    

      
Is this a blockchain?
No. There's no ledger, token, mining or global network. Each agreement has its own short chain of signed events, held by the parties to it. Hashes link the events and Ed25519 signatures authorize them, so any copy can be checked offline.
spec/04-inference.md · axiom A3

      
Where do our agreements live?
With the parties. A bundle is plain JSON that you can store in your CLM, ERP or a file share. Hosted services can store and route bundles for you, but nobody needs one to verify, because every evaluator recomputes the same verdicts from the same events.
spec/08-neutrality-charter.md: products built on the language may not claim to be required to use it.

      
How does it fit with EDI?
Side by side. The mapping guide shows how rosters, eligibility files and the X12 845, 844, 849 and 867 sets correspond to events and projections. The main gap in v0 is the distributor Role, and it's documented.
spec/07-mapping-guide.md

      
What's the license?
Universal Paper was created by Uppercentile, which offers it to everyone for free under open licenses: the specification and Term library are CC BY 4.0, the reference code and schemas are Apache-2.0, and the example agreements are CC0. No account, fee or license key is ever required. Anyone can implement it: if your code produces the same hashes and verdicts, it speaks Universal Paper. Licenses in detail.
