Quick start

A verified agreement in four commands.

The Python interpreter is a reference you can use, port or replace: if your code produces the same hashes and verdicts, it speaks Universal Paper.

  1. Install

    pip install universal-paper (Python 3.11+). It gives you the up command.

  2. Get a worked example

    curl -O https://universalpaper.org/examples/conventional/bundle.json

  3. Validate it

    up validate bundle.json checks every signature, hash and rule.

  4. Ask what’s owed, read it as a contract

    up derive bundle.json --at 2027-04-30T00:00:00Z then up render bundle.json --chain 0

As a library
import json
from universal_paper.engine import Bundle, Evaluator
from universal_paper.canon import content_hash
from universal_paper.report import snapshot

bundle = Bundle(json.load(open("bundle.json")))
ev = Evaluator(bundle)
chain_id = content_hash(bundle.chain_list[0][0])  # ChainId = hash of the genesis event
for step in ev.run(chain_id):
    print(step.index, step.event["kind"], "ok" if step.accepted else step.reason)
print(ev.status(chain_id, "2027-04-30T00:00:00Z"))  # "active"
report = snapshot(ev, "2027-04-30T00:00:00Z")  # statuses, tiers, prices, obligations

How it works

Three systems, three formats, one hash.

The GPO’s contract system, the supplier’s ERP and the member’s spreadsheet each keep their own format. All three compute the same agreement hash: sha256:b6f070ef…8f990f6d

  1. Write it oncePlain JSON built from standard Terms.
  2. Fingerprint itRFC 8785 canonical JSON, then SHA-256.
  3. Sign the fingerprintEd25519 over exactly that hash.
  4. Let the data do the mathEvery party derives the same fee.
  5. Catch any changeOne digit breaks the proof, offline.
  6. Keep private terms privateSeals hide values and still verify (A10).

Small enough to check by hand. Complete enough to run a contract.

Engineered properties

Each one maps to an axiom you can check.

Content-addressedRFC 8785

Every object is named by the SHA-256 of its canonical JSON. Same content, same name, on every machine.

DeterministicA4

State is computed from the chain, never stored. Two evaluators with the same events always agree.

Value-neutralA6

Terms define meaning, never numbers. The library can’t suggest a price, rate or period.

RicardianA8

The signed contract text is generated from the data, under the same hash. They can’t drift.

Bounded delegationA9

Agents act under Mandates. Anything outside the bounds is invalid for every evaluator.

Confidential by constructionA10

Seals hide private values while hashes, signatures and states still verify.

Proof, not trust

Every object has a fingerprint. Try to change one.

The same content gives the same hash on any machine, in any language. That is what lets parties trust the math instead of each other.

Questions

What developers ask first.

Is this a blockchain?

No. There’s no ledger, token, mining or global network. Each agreement has its own short chain of signed events, held by the parties to it. Hashes link the events and Ed25519 signatures authorize them, so any copy can be checked offline.

spec/04-inference.md · axiom A3

Where do our agreements live?

With the parties. A bundle is plain JSON that you can store in your CLM, ERP or a file share. Hosted services can store and route bundles for you, but nobody needs one to verify, because every evaluator recomputes the same verdicts from the same events.

spec/08-neutrality-charter.md

How does it fit with EDI?

Side by side. The mapping guide shows how rosters, eligibility files and the X12 845, 844, 849 and 867 sets correspond to events and projections. The main gap in v0 is the distributor Role, and it’s documented.

spec/07-mapping-guide.md

What’s the license?

The specification and Term library are CC BY 4.0, the reference code and schemas are Apache-2.0, and the example agreements are CC0. No account, fee or license key is ever required. Licenses in detail.
